## 0. 一句话说明这套东西

游戏里装了一个 mod（改过的 PCK），它每 0.12 秒把游戏内部状态写成 `out/br/state.json`，

## ⚠️ 0. 开打之前：会话权限必须是 danger-full-access

**这是第一位的，不满足后面全白搭。**

游戏要写 `%APPDATA%\Godot\...`（工作区外）并在沙箱外跑进程。
如果会话权限是 `workspace-write`（默认），启动游戏时会**申请提升到 danger-full-access**；
而审批如果是关的，申请会被**自动拒绝**，然后就卡在那里动不了。

**症状**：跑 `br-launch.py` 后游戏没起来，或者看到 `escalate sandbox to danger-full-access` 的审批请求。

**所以**：开新会话时就把权限档位设成 `danger-full-access`，别用默认的 `workspace-write`。

## 3. 规则（已修正手写版的错误）

> ⚠️ **先看你的风格**：`out/br/style.txt`（safe / balanced / aggressive）。
> 硬规则（1 血不吃药片等）所有风格都一样；**模糊局面按风格走**。
> 手册后面的策略表是"default 视角"，如果你的风格是 aggressive，有些地方该更冒险。



### 回合机制

- **每次装完子弹，玩家先手。** 所以"最后一颗空包打自己保住先手"是**没意义的** —— 下一轮本来就是你先。
- **打自己 + 空包** → 回合还是你的（白赚）
- **打自己 + 实弹** → 自己受伤，回合交给对方
- **打对方（无论空实）** → 回合交给对方

### 九种道具

| 道具 | 效果 | 关键点 |
|---|---|---|
| **小刀** | 下一发伤害 +1（1→2） | 空包不生效，白用 |
| **啤酒** | 退出当前膛内子弹 | 用来改变比例 / 跳过已知的坑 |
| **香烟** | 回 1 血 | **满血别用**；回血前先看 `start_hp` |
| **手铐** | 对方跳过下一回合 | ⚠️ **铐住后必须打对方**，打自己会浪费掉 |
| **放大镜** | 看下一发是什么 | 面板会显示「放大镜看到」 |
| **肾上腺素** | 偷对方一件道具 | **偷到即用**，不是放进自己格子；只有 7 秒窗口 |
| **电话** | 告诉第 N 发是空/实 | 从对话框读，见下 |
| **药片** | 50% 回 2 血 / 50% 扣 1 血 | ⚠️ **1 血绝对不能用**（扣 1 = 死） |
| **逆转器** | 翻转下一发 | 见下面的概率表 |

### 道具的正确心态（重要）

**默认动作：用。**

- 换小关就清空，带不走
- 不用 = 确定浪费
- 用错了 = 至少知道下次该怎么用
- **囤着 = 确定损失**

**所以别问「该不该用」，问「用了之后局面会变成什么样」。**

| 道具 | 用之前问自己 |
|---|---|
| 放大镜 | 看到之后我会做什么？看到实弹有没有小刀配合？ |
| 啤酒 | 退掉这发，剩下的是更好还是更差？ |
| 手铐 | 铐住他，我这一发打谁？剩几发？（见下面那个坑） |
| 香烟 | 我缺这 1 血吗？还是这回合更该抢节奏？ |
| 药片 | 赌命值不值？还是血量够、不必赌？ |
| 逆转器 | 现在空包多还是实弹多？翻转后对我有利吗？ |
| 电话 | 知道第 N 发是什么，能帮我做决定吗？ |
| 小刀 | 下一发**确定**是实弹吗？不确定就白用 |
| 肾上腺素 | 偷哪件？偷来的能**立刻**用出效果吗？ |

**如果你连续两回合没动过任何道具，回去看看 —— 大概是囤过头了。**

### 用道具 / 偷道具之前，先问：我现在最缺什么？

| 我缺 | 优先拿/用 |
|---|---|
| **命**（1~2 血，随时会死） | 香烟、药片（若无更好选择） |
| **信息**（不知道下一发） | 放大镜、电话 |
| **伤害**（对面快死了） | 小刀、逆转器 |
| **节奏**（想保住这一回合） | 手铐、打自己（如果是空包） |

**肾上腺素偷东西时尤其要问这个。**

**典型错误**：你 1 血，庄家手上有香烟和小刀。
去偷小刀想打伤害 —— **但你下一发要是实弹，你先死了，小刀没用。**

**活下来才用得上伤害。**

---

### 三个容易踩的具体坑

**① 只剩 1 发时，铐住庄家是浪费**

```
剩 1 发 → 铐住他 → 打 → 弹仓空 → 重新上弹 → 铐失效
```

手铐的价值是「跳过对方一个完整回合」。最后一发打完直接换新弹药，那个"跳过"落在空处。

**正确用法**：还剩 ≥2 发的时候铐。

**② 啤酒退出来的是什么，系统不会告诉你**

用完自己对比：

```
用之前：记下 live / blank 的数字
用之后：再看一次
哪个数少了，退出去的就是哪种
```

看不到变化 = 状态还没刷新，等 0.5 秒再读。

**③ 电话的结果去读 `out\br\dialogue_capture.txt`，别读 `state.json`**

对话文字屏幕上只停 3 秒左右，等你决策完再去读 `state.json` 早就清空了。

**抓取器已经自动在跑**（`br-launch.py` 启动时会起一个常驻的 `br-dialogue.py --follow`），
它每 0.12 秒扫一次 `dialogue` 字段，一出现就写进那个文件。

**所以用电话之后，直接读文件最后一行就是答案。**

**别做的事**：去 `state.json` 里翻 `dialogue` —— 那时候大概率已经是空的。

### 逆转器：看方向，别背死理

| 当前比例 | 用逆转器 | 结论 |
|---|---|---|
| 1实2空（33%实） | 空包→实弹，实弹概率变 67% | **正收益** |
| 3实2空（60%实） | 实弹→空包，实弹概率变 40% | **负收益，别用** |
| 1实1空（50%） | 还是 50% | **中性，别浪费** |
| 已知下一发是空包 | 变实弹 | **确定命中**（配小刀=确定2点） |

### 电话的读法

电话说的是**「从现在起第 N 发」** —— N=1 就是紧接的下一发，不是整轮装弹的固定位次。

- 例：剩 4 发、2实2空，电话说「第4发是实弹」→ 最末那发是实弹，前 3 发是 1实2空。
- **每打出一发，所有编号全体前移一位**：原来的「第4发」下一轮就叫「第3发」。
- **啤酒退掉当前那一发后，后面也全体前移**：原来已知的第 N 发，退一发后就是第 N-1 发。
- 所以每次局面变了都要**重新编号**，不能拿上一手的编号当这一手用。
- 好消息：如果电话说「第1发」，那就是直接知道了下一发，等于一个免费放大镜。

**2026-11-14 踩过的坑（用户当场指出）**：我把「第4发」当成整轮固定位次，
以为啤酒退一发后顶上来的就是那颗已知实弹，于是直接 `shoot:dealer`。
实际上退掉的那发本身就是实弹，顶上来的下一发是**空包** —— 打空了，白交回合，
庄家拿着那颗实弹反手打了我。**判断"啤酒之后下一发是什么"必须按前移后的编号重算。**

用 `tools\br-dialogue.py` 抓对话框：
```powershell
python tools\br-dialogue.py --sec 22    # 先起它，再用电话
```
结果写到 `out\br\dialogue_capture.txt`，内容是：
```
14:31:06 | 第四发子弹 / ...  实弹。
```

**推论方法（按"从现在起第 N 发"算）**：剩 8 发 = 4实4空，电话说第 4 发是实弹
→ 第 4 发锁死实弹，前 3 发是 4实4空减去这一发 = 3实4空
→ **当前这发（第1发）在 3实4空 里 = 43%**。（和旧写法结论一样，但旧写法的模型是错的，
一旦中途用啤酒退弹就会算错，见上面的坑。）

### 强化道具的常见套路

1. **手铐 + 小刀 + 打对方**：中了 2 点，打空对方跳过回合、下一发还是你的。
   **这套能兜住"打空"的损失**，是最好用的组合之一。
2. **放大镜 + 逆转器 + 小刀**：看清 → 空包翻成实弹 → 锯枪 → **确定 2 点**。
3. **肾上腺素偷逆转器**：对方有逆转器时，偷来翻掉已知的空包 → 确定 1 点。
4. **啤酒 + 电话做确定打击**：电话说第 7 发实弹 → 推出前 6 发里少一个实弹 → 用啤酒退到那发。

### 三条容易被忽略的硬规则（2026-11-13 用户补充）

**① 手铐一轮只能铐一次**
庄家带着铐时铐不了他；等他挣脱，就是他的回合，也铐不了。
所以：**看到 `庄被铐` 就别再想铐**，那一手白费。（循环里已经加了守卫，会跳过并记日志。）

**② 道具什么时候会没（按游戏源码核实过）**

| 场景 | 结果 |
|---|---|
| **普通模式第 1 关** | **根本没有道具**（`numberOfItemsToGrab = 0`） |
| **普通模式 第2关 → 第3关** | **清空**（这是普通模式唯一一次有道具可清空的切换） |
| **同一小关内的回合之间** | **保留**（например 第2关第1回合剩的，带进第2回合） |
| **无尽模式 每小关之间** | **清空**（1→2、2→3 都清） |
| **无尽模式 选加倍后** | 上一大轮**最后一小关**剩的道具，**带进下一大轮第 1 小关**；到第 2 小关再清 |

**源码依据**：
- `RestartBatch()`（加倍后重开）只把 `currentBatchIndex = 0` 然后调 `MainBatchSetup(false)`，
  **里面没有任何清空道具的调用** → 所以道具能继承
- 小关正常推进走的是另一条路径，会清空

**含义**：**道具带不出小关**。"囤到下一关再用"做不到。所以默认动作是**用掉**。

**③ 普通模式第三关：血量 ≤ 2 时回血通道被切断**
香烟抽了也不回血（**抽了就是白抽**）。所以第三关一旦掉到 2 血或以下，别指望回血，只能靠手铐/啤酒/逆转器活。
（无尽模式**没有**这条限制。）

### 血量相关的两条硬规矩

**① 1 血默认不吃药片** —— 但这是**经验法则，不是铁律**

50% 扣 1 = 当场死。**默认别赌。**

**但有些局面赌才对**：如果"这一轮被庄家打死的概率"**明显高于 50%**，
那么吃药的期望反而是正的：

```
情景：我 1 血，庄家下回合开枪的实弹概率 70%
  不吃：70% 概率被打死
  吃药：50% 回 2 血（活下来）+ 50% 扣 1（死）
      → 存活率从 30% 提升到 50%
```

**判断方法**：问自己「如果我现在什么都不做，下一轮我死的概率是多少？」
- **< 50%** → 别吃药（赌输就死，不值）
- **> 50%** → 可以考虑吃（反正大概率要死，赌一把）
- **拿不准** → 别吃

**同理**：其他"经验法则"也一样 —— 先算，再决定要不要套用。

**② 回血前先看 `start_hp`**
`state.json` 里的 `start_hp` 是**本大轮第一小关的血量**，回血上限就是它。
无尽模式每关血量随机 2~4，所以「我 4 血」不代表满血，可能上限就是 2。

## 4. 两张模式

### 普通模式（三大关）

- 第一关**没有道具**，第二关开始有
- 前两关死亡 → 浴室复活 → 点门1、门2 → 回**死亡那一关**
- 第三关死亡 → **天堂**：等镜头下摇 12 秒 → 点铁门 → 飞 15.6 秒 → 等"重启"字样出现 → 再等 2 秒 → 点重试
- 打完第三关 → 开箱领钱（左卡扣、右卡扣、箱盖）→ 结尾动画 → 回菜单

### 无尽模式（嗑药）

**进法**：洗手间里点**药瓶** → 选 ✔

**⚠️ 普通模式不要碰药瓶** —— 直接在洗手间开门（门1、门2）就行。
药瓶只在要走无尽模式时才点；点开之后选 ✘ 回到普通是多余的，会打断浴室流程。

（`br-run2.py` 的药瓶分支已经按这个逻辑实现：选「普通」时**什么都不做**，直接去开门。）

- 每大轮 3 小关，**死亡是真死**：回到洗手间，从**这一大轮第 1 小关**重来（不存档，所以关卡索引归 0）
- 死了之后药瓶会再次出现，要**重新选 ✔** 才回到无尽
- 打完 3 小关 → 算分 → 选择 **✔ 加倍** 或 **✘ 收手**
  - ✔ → 回到第 1 小关继续，下一轮赢了分数翻倍
  - ✘ → 领奖箱 → 结尾 → 回菜单
- **分数公式（不是按道具，是按时间）**：
  ```
  分数 = 70000 − (签名到打赢第三关的秒数 / 600) × 40000
  最低 10 分（打得超久就会兜底到 10）
  ```
  所以**打得快**才是高分的杠杆。

## 7. 这个会话里踩过的坑（别重复踩）

1. **`var x := obj.get(...)` 会让整个 autoload 解析失败** —— `get()` 返回 Variant，`:=` 推不出类型。用 `var x =`。
2. **`_dsh_cmd()` 里不能用 `d[...]`** —— `d` 是 `_dsh_dump()` 的局部变量，用了整个脚本编译失败。
3. **`Add-Type -TypeDefinition` 编译 C# 时必须 `-ReferencedAssemblies`** —— `-AssemblyName` 只是加载，不等于给编译器加引用。
4. **`$pid` 是 PowerShell 只读自动变量** —— 不能当自己的变量名用。
5. **按命令行模糊匹配杀进程会杀掉自己** —— 调用它的 shell 命令行里也有那个字符串。一律按 pid 文件杀。
6. **`.Replace(a, b, 1)` 是 Python 语法** —— PowerShell 的 String.Replace 只有两参数版本。
7. **`WS_EX_LAYERED` 单独不会闪，`Opacity < 1` 才会** —— 穿透用 `LAYERED | TRANSPARENT`，闪烁靠"不设 Opacity"避免。这两个变量要分开验证。

## 12. 决策前必须过的三个问题（2026-11-13 加，因为 AI 经常忘记用道具）

**每到决策点，照着念一遍，别跳：**

### ① 我现在知道下一发是什么吗？

| 手上/场上有 | 怎么知道 |
|---|---|
| 放大镜（我的） | `use:magnifying glass` → 面板显示「放大镜看到」 |
| 放大镜（庄家的）+ 肾上腺素（我的） | `use:adrenaline;steal:magnifying glass` |
| 电话 | `use:burner phone` → 看 `out/br/dialogue_capture.txt` |
| 啤酒 + 已知第 N 发 | 用啤酒把前面几发退掉 |
| 都不是 | 只能按比例猜（看「几空几实」） |

**知道是实弹、庄家只剩 1~2 血时，这就是必杀机会，别浪费。**

### ② 我能保证造成多少伤害？

**已知实弹时的伤害放大链**：

```
已知实弹 + 我有小刀            → use:handsaw;shoot:dealer = 2 点
已知实弹 + 我有逆转器（不需要）
已知空包 + 我有逆转器          → use:inverter;shoot:dealer = 1 点
已知空包 + 逆转器 + 小刀       → use:inverter;use:handsaw;shoot:dealer = 2 点
已知实弹 + 庄家有刀 + 我有肾上腺素 → use:adrenaline;steal:handsaw;shoot:dealer = 2 点
已知实弹 + 我有小刀 + 手铐      → use:handsaw;use:handcuffs;shoot:dealer = 2 点且对方不还手
```

**最容易被忘的一条**：**庄家有刀 / 逆转器时，用肾上腺素偷过来，立刻就是 2 点或 1 点**。
（偷到即用，不用放进自己格子，7 秒窗口）

### ③ 有没有更省的做法？

| 局面 | 更省的做法 |
|---|---|
| 对方 1 血、50/50 | 手铐 + 打对方：中了赢，打空他跳过回合 |
| 对方 1 血、我已知实弹 | 直接打，1 点就够 |
| 空包占优（>55%） | 打自己保回合，别浪费道具 |

### 50/50 怎么打 —— 看你的风格（没有绝对正确）

`1实1空` 时两种打法**胜率接近**，差别在**波动性**不是期望值：

| | 打自己（赌空包） | 打庄家（赌实弹） |
|---|---|---|
| 好分支（50%） | 空包 → 保回合 → 下一发实弹还是你的 | 实弹 → 直接打他 1 点 |
| 坏分支（50%） | 实弹 → **你扣 1 血**，还换手 | 空包 → **只换手，不掉血** |

**两个视角都成立**：
- 「不能赌自己掉血」→ 打庄家
- 「赌赢了我多打一手」→ 打自己

**这是偏好问题，别当定理。**

---

### 先选风格（读 `out/br/style.txt`，默认 safe）

| 风格 | 50/50 打谁 | 道具 | 药片 | 整体 |
|---|---|---|---|---|
| **safe 稳妥** | 打庄家 | **用，但挑收益明确的时机**（已知实弹才锯枪） | 只在 ≥3 血吃 | 少冒险，慢慢磨 |
| **balanced 中立** | 打庄家 | 按需 | ≥2 血吃 | 看局面临场判断 |
| **aggressive 激进** | 打自己（赌回合） | 能用就用，早用早收益 | ≥2 血就敢吃 | 追求节奏和翻盘 |

**风格只影响「模糊局面」的倾向，不影响硬规则**（1 血不吃药片这种，哪种风格都一样）。

**打法差异出现在这些地方**：
- 50/50 打谁
- 50% 出头的局面敢不敢打自己
- 手上有道具时先攒还是先用
- 血少时保守还是抢节奏

**想固定成某种风格**：在 `out/br/style.txt` 写 `safe` / `balanced` / `aggressive`。
不写就默认 `safe`。

# 自我复盘（只学道具，不学运气）

**手册只是起点。真正让你变强的，是你自己的对局。**

---

## ⚠️ 先记住：这个游戏运气占大头

**不要从单次结果里学规律。** 弹序是随机的，一次结果说明不了任何事。

### ❌ 不要这样学（这是把噪声当信号）

```
上次 1实1空 打自己死了，这次该打庄家
上次打自己连中了三次，所以打自己是对的
上次偷小刀赢了，所以残血偷小刀也行
```

**样本量 1 的"规律"等于没有规律。** 这么学只会越打越迷信。

### ✅ 正确的复盘问法

**不问「这次结果好不好」，问「在当时知道的信息下，这个决策的期望正不正」。**

| 该问 | 不该问 |
|---|---|
| 残血时我偷了小刀，但我当时**知道**下一发可能是实弹 —— 那我该不该先考虑保命？ | 偷小刀这局赢了，下次继续 |
| 只剩 1 发时我铐了人 —— 我**知道**打完就重装，那这个铐有没有用？ | 铐了这次赢了，所以铐得好 |
| 我有电话但没打就开枪了 —— 那是浪费信息吗？ | 这次没打也赢了 |

---

## 只学「可控的东西」：道具

**运气你控制不了，道具选择你能控制。所以复盘只聚焦道具。**

### ✅ 该学的

| 类别 | 例子 |
|---|---|
| **道具选择** | 残血时庄家有香烟和小刀 → 该偷香烟（保命），不是小刀 |
| **道具时机** | 只剩 1 发时铐人无用（打完就重装） |
| **道具组合** | 已知实弹 + 小刀 = 2 点；偷庄家的刀也一样 |
| **信息利用** | 有电话/放大镜不用就开枪 = 浪费情报 |
| **该用不用** | 连续两回合没动过任何道具 = 囤过头了 |
| **该省不省** | 花大代价（肾上腺素）去偷一个用不上的道具 |

### ❌ 不该学的

- 「上次打自己死了，下次打庄家」—— 运气
- 「上次这个决定赢了，继续保持」—— 运气
- 「机械数字：剩 N 发时如何」—— 靠算，不靠记

## 保持精简（重要）

**lessons.md 会越写越多，然后拖慢一切。必须压缩。**

### 硬规矩

| 限制 | 数值 |
|---|---|
| 总条数 | **不超过 12 条** |
| 每条 | **不超过 3 行** |
| 满了怎么办 | **合并相似的 / 删掉过时的 / 把两条概括成一条** |

### 写法

✅ 好（能改变下次的判断）：

**区别**：好的是「规律」，差的是「日记」。**记规律，不记日记。**

## 决策速度（很重要，别拖）

**每个决策点只做两次工具往返：**

1. `read out/br/need_decision.txt` —— **决策点里已经有全部信息**
   （局面 + 你的 lessons），**不用再读 state.json**
2. **同一条消息里**同时 `write think.txt` 和 `write decision.txt`

**不要这样**：
```
先 write think.txt → 想一会儿 → 再 write decision.txt
```
两次往返 = 多花 10~20 秒。打几十手下来就是十几分钟。

**为什么慢**：每一轮工具调用都是一次完整的模型请求。
上下文越长，每次请求越慢。**往返次数比上下文长度更致命。**

## 关于上下文（给用户看的）

会话打久了，上下文会涨，决策会变慢 —— **这是正常的**。

**DSH 会自动压缩**，但那本身也要时间。

**建议**：

| 情况 | 怎么办 |
|---|---|
| 打了几十手，明显变慢 | **换一个新会话**（新会话读手册 + lessons.md 就能接上） |
| lessons.md 太长 | 会拖慢每次决策点，**控制在 12 条以内** |
| 觉得整体慢 | 先看是不是工具往返太多（见上面） |

**换会话不会丢东西**：`lessons.md` 在文件里，新会话读一遍就继承了你的训练成果。

## 道具名用词（别自己改）

游戏里叫 **放大镜**（英文 **magnifying glass**），**不是"镜子"**。

镜子是反射，放大镜是透镜 —— 差别很大的两样东西。
写决策时用完整名字：`use:放大镜`。

**英文版写 `magnifying glass`，不要写 `mirror`。**

> 防御：即使写了"镜子"/"mirror"，系统也会自动当成放大镜，
> 但**别依赖这个兜底** —— 写对更省事。

## 写决策后，最后自查一遍（防编造道具）

**你准备写的每个 `use:X` 和 `steal:X`，X 必须真的在手上/对面有。**

典型错误（实际发生过）：想着"偷庄家的刀"这个套路很赚，
顺手把 `use:adrenaline` 也写上了 —— **但你手上根本没有肾上腺素**。

**现在系统会整条退回重问。连续两次就只执行 shot，道具全放弃。**

所以写完扫一眼「我的:」那一行，确认名字都在里面。

# 怎么写出决策（省 token 的关键）

**每个决策点只做 2 次工具调用。** 这不是建议，是必须 —— 一手多一次请求，
一局下来成本翻倍。

## 标准动作：用 `tools\br-set.py`，一条命令搞定

**别自己拼 `python -c "..."`** —— 中文加引号在 PowerShell 里很容易撑破，
写失败了还得重试（重试 = 多一次完整请求 = 多花一份钱）。

**用现成的脚本：**

```powershell
# 对局决策：think + decision 一起写
python tools\br-set.py "50/50 safe 打庄家" dealer

# 选择题（药瓶/菜单/加倍）：只写 decision
python tools\br-set.py yes
```

**输出只有一个 `k`** —— 既确认成功，又不占 token。

**它内部先写 decision 再写 think**，所以就算 think 那半出问题，主循环也不会卡住。


## 不要做的事

| 别做 | 为什么 |
|---|---|
| **别用 `write` 工具** | 这两个文件被循环频繁删除重建，`write` 会报 `file changed since it was read`，失败那次也是完整请求 |
| **别分两次 pwsh** | 一次能写完的事，两次就多一倍请求 |
| **别让命令有输出** | stdout 会进上下文。想要确认就 `print('k')` |
| 别先写 think 再"想一想"再写 decision | 那是两次往返 |

## 例外：选择题决策点（药瓶 / 菜单 / 加倍）

那几种**不需要 think.txt**，直接一条命令写 decision：

```powershell
python -c "open('out/br/decision.txt','w',encoding='utf-8').write('yes'); print('k')"
```

## 一共几次调用？

| 类型 | 调用数 |
|---|---|
| 对局决策点 | **2**：read + 一条 pwsh |
| 选择题 | **2**：read + 一条 pwsh |
| 外加每手的**等待唤醒** | +1（不可避免） |

**总共 3 次。超过 3 次就说明你在乱花。**

## 读决策点必须用 `read` 工具，绝对不能用 pwsh

**这条是硬的。**

用 `pwsh` 读 `need_decision.txt`（`Get-Content`、`type`、`cat`）会把中文变成乱码：

```
鎴?2 : 搴?2 | 1 瀹?2 绌?鍓?3 鍙?| 鎴戠殑: 鏃?
```

（UTF-8 被当成 GBK 读了）

**然后你就会凭字形去猜** —— 猜错就会写出不存在的道具。
实际发生过：把「手铐」看成「肾上腺素」，然后写了 `use:adrenaline`，
整条决策被退回。

**因为：控制台输出的编码是死的，文件读取是准的。**

| 要读什么 | 用什么 |
|---|---|
| `need_decision.txt` | **`read` 工具** |
| `state.json` | **`read` 工具** |
| `lessons.md` | **`read` 工具** |
| 想确认文件写了没有 | 用 `pwsh`（只看有没有，不看内容） |

## 连着做，别每手都结束回合

**如果一切正常，可以在一轮里连续处理多个决策点** —— 每手少一次"唤醒"请求。

```
read 决策点 → br-set.py 写 → （sleep 轮询）→ read 下一个 → ...
```

**但注意**：
- 中间要有 sleep（不然忙等空转）
- 一手的**乱码风险、超长等待**要盯住
- 觉得不对就停下来，别硬撑

## 每次决策前，先看一眼血（重要）

**血是这个游戏里唯一「用掉还能拿回来」的资源。**
2 血以下再挨一发就死 —— 那时候你手上再多道具也没用。

所以每手决策，按这个顺序过：

### 第一步：我几血？

**香烟：只要不满血就抽。**

不是「快死了才抽」—— 而是**掉一点就补一点**。原因：
对面一手能打出 **2 点甚至更多**（逆转器 + 小刀 = 空包也变 2 点、
已知实弹 + 锯枪 = 2 点）。**你 3 血看起来安全，其实一回合就没了。**

**留着香烟=留着保险不用。它换关就清空，带不走。**

| 血量 | 该怎么做 |
|---|---|
| **满血** | 不用抽（抽了也白抽） |
| **掉 1 点及以上** | **有香烟就抽**，先补回来再打 |
| **≤2 血** | 回血优先，除非这手能直接结束对面 |

**例外（可以先不抽）**：
- 这手能**确定**打死对面（已知实弹 + 刀 + 对面 ≤2 血）
- 对面被铐住 + 你确定这发能中

### 第二步：手上有没有回血道具？

| 有 | 该怎么做 |
|---|---|
| **香烟**（回 1 血） | **先抽，再看局面**。回 1 血可能就是能不能再挨一发 |
| **药片**（50% 回 2 / 50% 扣 1） | 评估赌不赌。1 血时扣 1 = 死，但如果你下轮必死，赌也是理性 |
| **都没有** | 只能靠打法和运气 |

### 第三步：例外 —— 什么时候先不回血

**只有这几种情况可以跳过回血，直接打：**

- 这手能**确定**打死对面（已知实弹 + 刀，对面 ≤2 血）
- 对面已经被铐住 + 你确定这发能中
- 回血会**浪费掉唯一的机会**（比如对面 1 血，你打电话知道下一发是实弹）

**除了这些，低血就先回血。**

---

### 一个真实的错误案例

```
我 2 : 庄 3 | 3实2空 剩5发 | 我的: 小刀×1、啤酒×2、香烟×2
→ 直接打庄家，什么都没用
```

**错在哪**：2 血、手上有 2 根香烟（能回 2 血），3 实 2 空 = 60% 实弹。
**这手应该先抽烟回血**，而不是拿 2 血去赌 60%。

**它优化的是「这一发」，不是「活下来」。**

## ⚠️ 打第二局**不要**重跑 br-launch.py

**注意一个例外**：`br-launch.py` 刚启动后的**第一次**不会问「要继续吗」——
它直接发 `menu_start` 把游戏开起来（不然新用户第一眼看到的是"游戏开了但停在浴室不动"）。
**之后的每一局才问。**

**主循环不会死。** 一局打完回到菜单，循环会自己问：

```
[决策点] 一局结束了，要继续吗？
  yes   再开一局（menu_start）
  no    停在这里
```

**写 `yes` 就开下一局了** —— 同一局会话里连续打，不需要重启任何东西。

---

## ‼️ 「一局」怎么算：两种模式不一样

**用户说的「打一局」是哪个一局，取决于模式。别搞混。**

| 模式 | 一局 = 什么 | 什么时候算打完 |
|---|---|---|
| **无尽模式**（药瓶选 yes） | **一次死亡** | **死一次就是打完一局** |
| **普通模式**（药瓶选 no） | **打完拿到钱** | **打完 3 小关、开箱拿到钱 才算一局** |

**所以：**

- **无尽模式里死掉** → **这局结束了，回到菜单**（要接着打就再开一局）
- **普通模式里死掉** → **这局没结束**！选「重试」，从**同一个小关**重新打
- **普通模式里没拿到钱就退出**（天堂界面选「退出」）→ **不算打完一局**

**一句话：无尽数死亡，普通数拿钱。**

## 🎯 指定打几局：写 `target_games.txt`

**不写这个文件 = 每局结束都问你「要继续吗」。**

**想让它自动连打 N 局**，先写：

```powershell
'3' | Out-File -Encoding utf8 out\br\target_games.txt
```

**它会：**

```
打完第 1 局 → 局数 1/3 -> 自动开下一局
打完第 2 局 → 局数 2/3 -> 自动开下一局
打完第 3 局 → 已打满 3 局（目标 3）-> 停下来问「要继续吗」
             并自动删掉 target_games.txt、把计数清零
```

**进度可以看 `out\br\games_done.txt`。**

**⚠️ 计数点是「回到菜单」，所以：**
- **无尽模式**：死一次 = +1（符合「数死亡」）
- **普通模式**：**退回菜单才 +1** —— 中途死掉选「重试」不会加，符合「拿到钱才算一局」

## 🔓 停下来了怎么继续

**答过 `no` 之后循环会安静待着（不再反复问你）。想继续有两种办法：**

**① 答一次决策点**（如果它还开着）：
```powershell
python tools\br-next.py yes
```

**② 直接让 mod 开一局**（最保险，不依赖循环）：
```powershell
'menu_start' | Out-File -Encoding utf8 out\br\cmd_menu.txt
```

**游戏离开菜单后，循环会自动恢复。**

**另外**：**答了 `yes` 但 `menu_start` 没生效**（游戏还在菜单）—— 循环会在 **60 秒后自动重试一次**。

### 什么时候才真该重跑

| 情况 | 要不要重启 |
|---|---|
| 一局打完，想再打一局 | **不要**，答 yes |
| 想换普通/无尽 | **不要**，药瓶那手选就行 |
| 改过 `tools/` 下的代码 | 要（循环不会热加载） |
| 循环真的死了（`run2.log` 有「主循环结束」且不再更新） | 要 |
| 游戏窗口没了 / 黑屏 | 要 |

**判断方法**：看 `out/br/run2.log` 还在不在写。在写就活着，别动它。

**注意**：`br-launch.py` 会清空 `run2.log` 重新写，所以"重启过"会丢掉上一局的日志。
**别把它当成常规操作。**

# ⚡ 推荐写法：用 `br-next.py`，一手只花一次请求

**前面那套「read + br-set.py」是一手 3 次请求。用这个脚本能压到 1 次。**

## 用法

```powershell
python tools\br-next.py "50/50 safe 打庄家" dealer
python tools\br-next.py yes                      # 选择题
```

**它干四件事**：

1. 写 `decision.txt`（先写它，主循环就能往下走）
2. 写 `think.txt`（面板显示）
3. 等下一个决策点出现
4. **把新局面直接打印出来**

## 它会输出什么

```
k
=== 第 1 手的新局面 ===
我 2 : 庄 1 | 3 实 2 空 剩 5 发 | 我的: 小刀×1
--- 你的教训（lessons.md）---
## 香烟不满血就抽，别等到快死
...
--- 回答前 ---
1) ...
```

**看到 `=== 第 N 手的新局面 ===` 后面那段，就是下一手要读的东西。**

**不用再 `read` 了 —— 它已经在你眼前。**

## 为什么省

| 做法 | 每手请求 |
|---|---|
| read + br-set.py + 等 | **3** |
| **br-next.py** | **1** |

**76% 的时间花在"等局面 + 传话"上，不是在思考。**

## 什么时候别用它

- **想先看看局面再决定**（比如刚进新关卡）→ 用老办法 `read` 一次
- **脚本报错**（超时 / 主循环停了）→ 它会说人话，照它说的查 `run2.log`
- **不确定它靠不靠得住** → 随时可以回退到 `read` + `br-set.py`

## 一个回合不要拖太久

**默认只等 1 手就返回**。连续等很多手的话，一个回合会变得巨长，
中间任何一处出错都很难收拾。

**想连等**：`--max 3`，但**做完立刻回头看一次** `run2.log`。

# 三种写法对比（按成本）

| 写法 | 每手请求 | 什么时候用 |
|---|---|---|
| **`br-next.py`** | **1** | 默认用这个 |
| `read` + `br-set.py` | 3 | 想先看局面 / 脚本报错时 |
| `read` + `write` 工具 | 4+ | **别用**（会被文件策略拒，白花请求） |
